# 营养模板与当日目标业务数据合同

真实源以当前仓库 `src/services/nutritionStrategyService.ts`、`src/services/nutritionTargetService.ts`、`src/db/types.ts`、营养周期服务为准；此文件限定行为，不宣称现有 API 已覆盖所有新 UX。

## 对象隔离
- `nutritionStrategyTemplates`: 模板定义；`nutritionStrategyVariants`: 一个模板可有多个日方案；`nutritionStrategyPhases`: 实际使用的阶段与开始/结束业务日；`nutritionTargets`: 逐日期保存的真实目标，可能来源于手动、饮食模板、strategySelection、cycleSelection 等。
- `nutritionCycles`、`nutritionCycleDays` 是独立日程排程与应用来源；不得因设置目标误操作、覆盖或取消它们。
- 食品/食物实际日志是已经发生的健康事实；改变今日目标不影响 FoodLog 及其快照。
- 已归档模板应保持数据完整和现有禁用规则，不能为了展示选择列表而自动重新启用它。

## 状态与提交
1. **查看**：读取可用/已归档模板以及目标/日期；查询与预览不发生写入。
2. **选模板**：仅暂存用户选择；若选择当天已有效模板，可直接选日方案；若模板未启用/当天非有效，必须经过启用确认。显示已启用的单一标签与历史阶段区分。
3. **启用**：明确起始业务日期、现有活动阶段结束日期。调用现行启用服务的完整校验/事务；仅批准的阶段语义变化允许提交，不能清除历史目标/周期；若日期会造成重叠或冲突，安全阻止并解释，不可悄悄覆盖。
4. **选日方案**：只是预览。对“当前选中日、当前选中模板、真实方案和现有目标来源”做新鲜性复核；变更后需重选/重新确认。
5. **应用当日**：独立二次明确操作，仅替换选中日期的目标；保留 `strategySelection` 来源/快照语义，未设置的宏量不推断为0；旧目标冲突由当前服务约束或用户显式选择处理，不得自动覆盖不可证明的来源。
6. **新建模板**：保存前日方案仅存在内存草稿。完整模板保存成功不自动启用、不产生 nutritionTargets 和其他日期写入。新模板应立刻在选择器出现，再由用户自主启用/应用。
7. **手动目标**：沿用原服务和已有目标编辑/删除能力；入口从次级动作到达，不减少功能。用户关闭编辑器或失败重试不得改变已保存目标。
8. **刷新/重开/跨标签**：已启用状态和已保存目标依据真实 Dexie 保存结果而非临时标签；保证“同一日期只能有一个有效模板”，模板/phase变化导致陈旧预览失效。

## 边界测试必备
- 空模板列表；单个已保存但未启用模板；多个可用模板含一个当前有效；全部归档；无日方案；仅有手动目标；来自营养周期/饮食模板的当前目标；过去和未来业务日期；同日切换模板；切换取消；保存模板失败；源数据在确认前跨标签变动；重复快速点击；应用失败后的恢复。
- 每个测试声明允许变化的 store/row IDs；其余所有健康事实、任务/计划、旧目标、旧阶段、周期、共享资料/设备配置保持不变。不得对真实个人数据库执行破坏性测试。
- 不借“模板选择”修改当前已批准的按区间永久删除规则或范围；保留六类/九类级联删除路径的双重确认与数据保护。
