# Codex 正式开发指令：管理中心 v0.6.1 竖向版

## 1. 项目背景
FitLog Lite 是 iPhone 优先、本地优先的 Vanilla TypeScript PWA。用户对右上角「···」进入的「管理与设置」不满意，已确认旧设计原型 v0.6.1 单列纵向版。上一轮导航闪帧修复 v0.4.1 已上线，不能回归。

## 2. 目标
将**管理中心入口、视觉、信息分组及其二三级管理页面的统一设计**按 v0.6.1 实现，改善入口查找、信息层级、搜索和逐级返回。保持浅色、柔和、易读，不引入 v0.7 大面积深绿与强烈 Field Edition 风格。

## 3. 当前实现事实与需核实事项
已从 GitHub 读取 `src/main.ts` 的 `showManagementHub`（约 1046 行），现为分组列表，绑定真实 13 个入口：食物库、动作库、训练模板、饮食模板、营养模板、习惯、导入数据、备份与恢复、GitHub 同步、外观、AI 设置、版本诊断、关于。`src/ui/managementWorkspace.ts` 已实现同一原生 dialog 的路由栈、返回、关闭、scroll 恢复、dispose；`src/styles/primitives.css` 已统一六种实体管理器的列表与表单组件。**先核实已有能力，做差异化升级，不要重新实现一套管理工作区。** Codex 必须先读完整 AGENTS.md、LATEST_DEV_REPORT.md、docs/CHAT_CODEX_WORKFLOW.md、docs/UI_INTERACTION_SPEC.md，检查最新 main 与相关 CSS、测试。

## 4. 已确认行为
- 管理中心采用单列竖向分组：图标、标题、辅助说明、右箭头；入口总数和原有业务含义完整保留。搜索支持快速过滤/定位入口，搜索结果可直接进入对应真实页面，清空可恢复全列表。
- 分区清晰：饮食资料（食物库、饮食模板、营养模板）、训练资料（动作库、训练模板）、个人计划（习惯）、数据与安全（导入、备份与恢复、GitHub 同步）、设置与工具（外观、AI 设置、版本诊断、关于）。这是推荐的 5 组、13 入口；具体文字以批准原型为视觉基准，若与真实功能名称冲突以真实业务为准并记录差异。
- 同一管理 dialog 内 Hub→列表→编辑/子页→Back 逐级返回；标题与真实父级一致；X 在任意层关闭整个管理工作区。返回后保留合法查询、滚动和未保存的非敏感 UI 草稿，保存后刷新真实服务数据；关闭后再次打开从 Hub 顶部开始。
- AI→语音、资料库→编辑器、备份/同步等实际路径完整，不能把业务页替换为通用假表单；现有独立入口行为也保留。
- 列表、表单、确认、空状态、无搜索结果、错误与加载状态有一致的排版；44px 点击区、语义化按钮、键盘焦点和 VoiceOver 标签保留。

## 6. 修改范围及禁止事项
允许管理 Hub 的模板、样式、搜索/过滤逻辑，以及为二三级视觉一致性必要的共享管理组件、相关测试、规范和证据。**禁止**整体换肤、五主 Tab 重构、导航协调器重写、训练 Sheet/计时/Autosave 重构、Food 日期滑动改动、趋势/日历/报告计算改动、无关服务重构。不能关闭再打开 dialog 来模拟返回，不能造成页面闪烁/滚动跳动。不得为视觉目的新增重依赖或更换框架。

## 7. 数据安全及兼容性
保护 `fitlog-lite-db`、Dexie13/IDB130/22 stores、Backup14/Restore1–14、Sync1/envelope1、历史 FoodLog/Workout 不可变快照、设备本地业务日期、AI/Voice 配置、所有用户记录。不得清空或迁移数据库，不更改业务服务的读写语义。搜索仅为 UI 过滤，不应持久化敏感查询；编辑保存走现有真实服务和校验。Restore/Sync 的确认与事务不弱化。

## 8. 自动化与功能验收
执行仓库规定的 npm ci、类型检查、1143 单测或**最新真实数量**、build、44 个既有门槛或**最新适用清单**；按项目脚本实际读取后运行，不机械沿用旧数。专项至少验证：13/13 入口存在并打开真实业务；搜索/清空/无结果；每组分区及键盘可达；Hub→六类资料库→新建/编辑→返回；AI→语音→返回；备份/恢复/同步的真实状态与确认；外观主题；任意层 X；快速开关/返回；重复导航资源释放；管理打开期间主页面状态保留；关闭后五 Tab 无闪烁/二次落位；Restore 后旧筛选兼容；数据库合成档案前后摘要一致。失败留证，不降低原断言。
