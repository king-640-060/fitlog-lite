## 2. 不能再次出现的真实交互问题（回归负例）

- **饮食模板重复餐次**：每个食物多一行“早餐”下拉、上下箭头/删除工具条，占用大量高度。批准改为顶部餐次一次选择，仅显示当前餐次的条目（前提是整日模式）。
- **排序直接换位**：手指按左侧把手，原 v0.3 仅跨越项目时 `insertBefore` 立刻交换，视觉对象没有跟手；录屏 `references/user-evidence/07_用户录屏_原拖拽不跟手.mp4` 为负面证据。批准为悬浮对象实时跟手+占位+相邻让位+松手提交。
- **餐次切换宽度变化**：某餐项数不同导致切换时内容宽度改变；批准固定宽度页面轨道。
- **滑动只移动导航胶囊**：报告页下方内容没随手指一起滑；批准三级页面内容自身跟手。
- **报告滑完弹/横跳**：原型曾用外宽计算内页位移，产生 32px 错位；不得在结束时通过重置 scroll 造成跳动。
- **日历右侧出现额外纵向滚动部位**：非当前的较长报告页面撑高邻页；各页高度/纵滚应独立。
- **日历→报告结束后下移**：曾经导航层在 settle 后插入，导致下面整体额外下移约 124px。两级导航必须先布局且和报告页一起横向进入。
- **第三级把第二级一起带动**：切日报/周报/月报时，“日常综合报告/营养周期报告”不能随之滑动；必须三个互相隔离的水平轨道。此为用户反复强调的最高验收要求之一。
- **报告标签/内容错配**：在周期报告选周报、返回日常报告时，曾出现标签与内容不一致；真实数据状态必须统一。
- **指定食物两状态 footer 异位**：按钮漂浮、间距大、遮挡/键盘/Safe Area 不一致，应遵循已有 Sheet 正式合同。
- **新增动作不可编辑名称**：v0.8 原型只有“新动作 N”固定标题；v0.9 已补新增名称与“改名”入口，取消无损 set。

## 3. 三级独立导航交互边界图

```text
进度
└─ 一级轨道 [趋势] [日历] [报告]     ← 一级切换整页；下级随报告页进入/退出
   └─ 报告页中的二级轨道 [日常综合报告] [营养周期报告]
      └─ 日常报告中的三级轨道 [日报] [周报] [月报] [自定义]
         └─ 当前报告内容页（与三级同步横滑）
```

**固定原则**：三级切换不使二级及一级移动；二级切换不使一级移动；一级切换报告时二级/三级作为完整报告结构一次入场。仅活跃层级响应其对应的导航/内容手势，输入、垂直滚动/图表横滚、系统边缘返回享有既定优先级。

原型内营养周期的第三层可能只是 UI 演示：生产 `renderCycleReportsPage` 目前提供自己独立的真实筛选/周期选择。不能伪造不存在的真实日报/周报/月报分析；如设计期望与已有领域业务不一致，明确列举冲突后依仓库要求交回用户，而不是把“演示数字”带进报表。

## 4. 原型与生产服务分工

| 层面 | v0.9 原型可约束 | 真实生产仍由服务与合同决定 |
|---|---|---|
| 饮食 | 单餐分组与跟手排序视觉、相邻整页切换 | `DietTemplate.items`、mode/meal、fallback 营养快照、模板应用和 FoodLog 真正写入 |
| 训练 | 动作条紧凑、拖拽顺序、名称输入/改名 UX | Exercise 库 / WorkoutExercise 快照 / Workout.name、Autosave/指纹和完成事务 |
| 报告 | 三级各轨道独立、导航稳定、跟手翻页、零纵向跳动 | 真实日报/周报/月报/自定义统计、营养周期筛选和快照语义 |
| 指定食物 | 统一底部 CTA 与 Sheet 卷动布局 | 真正摄入确认、FoodLog 和 NutritionTarget、现有推荐优化器与旧记录 |
