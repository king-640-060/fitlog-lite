## 2. F1 修复 100g 显示与输入

- 复现截图上的「100g」问题，区别 **控件显示**、**默认克数**、**实际存储** 三件事；找到可验证根因（若无法复现，应展示输入尺寸和属性验证，不能说已修复未知原因）。
- 使数字与单位清楚分离；默认 100g 如当前创建行为仍可保留，但可自由编辑且不覆盖别的文字；input focus、中文/数字键盘、超长商品名、极限宽度、200% 字体通过。
- 输入无效、分数克数、边界和营养快照回退行为按原合同；只改变 UI/校验确需改处。修改保存后重新打开必须保留数值。

## 3. F2 一日饮食模板的持久化业务能力

- 现状：`DietTemplateItem` 没有 meal 字段，`dietTemplateFromLogs` 不保留 meal，`applyDietTemplate` 创建 FoodLog 时没传餐次。只改 UI 不合格。
- 为模板定义**显式模板类型/模式**及每项的可选 `MealType`（或等价向后兼容方案），保持旧模板内容、ID、顺序、fallback、可选营养目标。新建支持「组合 / 单餐」和「整日」；整日能逐餐次选择食物与克数，增加、移动、删除和保存；同日记录保存为模板时保留原来的 meal。
- 复制、编辑、管理列表、预览、应用、周期安排入口、来源已被删除时的 fallback 和 nutritionGoal 冲突机制全部贯通。按餐次应用时显式处理单餐模板的目标餐次，旧模板没有 meal 的旧行为不变；**不可无提示地把旧模板的所有食物归类为早餐**。
- 套用模板只在用户确认实际摄入、选择日期/餐次与处理冲突后写真实 FoodLog；未来日期继续按现行禁写/预览约束处理；不能自动回填营养周期排程日。
- 建议优先实现为向后兼容的可选字段；若完整备份数据格式合同发生变化，遵循 `AGENTS.md` 对 Backup/Restore schema 升级的要求，新增 frozen fixture（不得改写旧快照）、Restore1–当前兼容与事务回滚。任何需要历史破坏性迁移或业务含义冲突的事项，**在该部分停止并请求用户确认**。

## 4. F3 饮水输入统一

- 同时检查 Today 恢复卡片 `src/ui/recovery.ts` 和 Progress 饮水弹层 `showWaterRecord`：只保留 `+500 ml`、`+1000 ml` 两个等权快捷按钮，外加低强调的「自定义饮水量」；不再以 250ml 作为主动作。
- 使用现有语义 Token 与 Sheet，不能为 500/1000 设置高低级差异配色；输入/记录保持唯一事务与原撤销 Toast、历史管理、精确删除和趋势更新。重复点击/失败/离线处理完善。
- 自定义仍允许合法的实际 ml，遵循服务现有正数/最大值合同；记录前显示明确的数量和日期，不以参考值或未选择的预设替用户输入。

## 5. F4 日期详情十类卡片紧凑而不缩窄

- 以 v0.4 日期详情作为批准视觉：**整行两列铺满、宽度不变，两侧不增加空白、卡片标准高约 73px**。
- 调整 `.calendar-detail-sheet` 与 `dailyRecordsHtml` 所属布局；食物卡在 11 条真实记录下只呈现紧凑两行概览，不在概览再显示「已保存营养目标」。点击展开仍能看到实际摄入与保存目标的完整独立事实，不丢可访问性。
- 十类空、有数据、超长名称/单位/数值、动态 liveQuery 更新、展开收起和已有精确删除不回归；不要使用固定 `width`、溢出裁剪或不必要的挤小字号解决宽度问题。
- 200% 字体与屏幕阅读器可增长高度，确保重要文本完整可读；真实 320px Safe Area、屏幕键盘、深浅色无横向溢出。

## 6. F5 模板管理入口与安全删除

- 饮食模板已有 `data-delete-diet-template`，但埋在编辑底部；提供可发现的管理入口并沿用现有历史保护，不重复造一套破坏性业务服务。
- 营养模板只有 `archiveNutritionStrategy`；为**确认无任何历史/排程/已保存目标引用**的模板新增真正永久删除，删除模板及隶属日方案时必须事务处理、预览真实影响范围、确认前后复核引用和来源版本。
- 有当前/历史策略阶段、当日 `strategySelection`、排程日 `nutrition` 引用或相关业务快照引用时，**禁止永久删除**，保留可用归档/切换/原因说明路径。不可通过 UI 隐藏入口绕过验证。未使用模板删除、已用模板归档有不同文案/危险颜色/成功通知。
- 归档继续保留所有历史目标和阶段，不删除已有周期报事实；旧归档模板的管理可见性不回归。
