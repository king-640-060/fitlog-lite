# 数据安全与兼容边界（必须核验）

**已有正式版本：** `fitlog-lite-db` Dexie V13 / IndexedDB V130 / 22 表、Backup14、Restore1–14、Sync1 / envelope1。项目当前真实 main 为准；这些合同**不得改变**。

## 允许写入矩阵

| 交互 | 允许写入 | 绝不修改 |
| --- | --- | --- |
| 食物搜索/勾选/取消/建议计算/微调预览 | 0 表 | 所有表、配置 |
| 选模板/取消本轮选中 | 0 表 | phases、templates、targets、cycles、所有健康记录 |
| 已确认的模板启用 | 仅既有合法 phase 改动 | NutritionTarget、健康事实、其余阶段历史的非法变化 |
| 用户明确确认应用当天目标 | 仅所选 date 的目标快照 | 其他日期目标、现有周期、已保存食物/体重/饮水/睡眠/训练 |
| 已确认实际吃下指定食物后记账 | 仅新 FoodLog IDs（按原服务） | NutritionTarget、Food 主数据、其他健康事实 |
| 取消/失败/竞态陈旧提交 | 0 表（或事务整体回滚） | 全部存活数据 |

## 冻结验证

- 在隔离合成档案上保存 22 张表/8项配置的事前逐表规范化 hash、完整记录 ID 集合和旧 Backup14 恢复 fixture；功能尝试、关闭重开、在线/离线、发布升级各阶段复核。
- 针对 FoodLog 提交运行重复点击/失败注入/跨标签修改源数据/日期切换/其他日期存在历史记录；必须 all-or-nothing、仅新增预期 ID。任何自动推荐数量都不得在预览中成为真实摄入。
- 针对模板选择，所有 22 表对比完全相同；实测“删除今天目标后再开”的状态仅通过 UI 隔离读取测试初始化，而不删除用户真实资料。
- 禁止清空/迁移真实 DB，禁止在个人档案上做破坏性恢复/同步测试；不得修改备份/恢复/同步 parser 或 schema 来实现界面交互。
- 保留联合 v0.3、饮水 Sheet v0.1、营养目标模板 Sheet v0.2、周期报告、永久区间级联删除、计划、趋势高度/日期及原 iPhone Pending 状态。
