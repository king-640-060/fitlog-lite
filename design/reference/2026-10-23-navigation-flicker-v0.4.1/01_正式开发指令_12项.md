# Codex 正式开发指令：FitLog Lite 主 Tab 闪烁专项 v0.4.1

## 1. 项目背景

FitLog Lite 为 Vanilla TS + CSS + Vite、Dexie/IndexedDB local-first iPhone PWA。v0.4 先行实现了五个主 Tab 的跟手滑动与邻页预览，Application `32d382d426db696727f3161e81e007f6ce7f850f`，END `c78c428044a5ca80591d049fcf1d00cf680a0eeb`。用户现有真实录屏确认所有主 Tab 在过渡末端可能发生肉眼可见的闪烁、内容刷新，训练页的二次落位最严重。**该项覆盖先前“主导航视觉连续性 PASS”的结论，需重新修复及实测。**

## 2. 唯一目标

- 用户滑动或点击切换 `今日 → 计划 → 饮食 → 训练 → 进度` 时，目标页从进入视野到切换完成必须**视觉连续**；无亮／白／底色闪帧、整页重绘感、卡片二次入场、布局二次跳变。
- 同时恢复页面的真正交互能力、事件监听、无障碍、独立滚动位置、订阅和清理；不能以无交互的“预览照片”或永久不销毁的全局缓存冒充修复。
- 原有跟手横移、胶囊同步、回弹、任意 Tab 点击、滚动与手势优先级不回归。
- 训练含真实内容、历史入口、空态、存在进行中 Workout 三种状态都平稳。

## 3. 当前可核实事实与根因假设

当前 main（实施前重检）`src/ui/horizontalNavigation.ts`：
- `prepare()` 调用 `prepareTabPreview()` 创建 `.page-preview`；`draw()` 以 transform 将其推入视野；`finish()` 完成滑动后再调用 `options.commit(target)`。
- `src/main.ts` 的 `commit` 为 `activeTab = tab; await render()`。
- `render()` 在已有根节点时仍 `.topbar.replaceWith(...)`、非特殊情形 `#view.replaceWith(...)`，然后重新 `renderTodayPage / renderPlanPage / renderFoodPage / renderWorkoutPage / renderProgressPage`。
- 预览路径的 renderers 多有 `if (preview) return`、不绑定正式控件／订阅；预览去除 `id`、`aria-live`，置 inert／aria-hidden。**绝对不能简单把只读预览 DOM 直接改成可交互正式页面。**
- 在 `finish()` 的 `options.commit()` await 完成后才 `clean()` 移除 preview。这是明显的显示内容双次生成／交换位置，**与录屏症状高度一致，但尚须时间线与帧证据核实真正可见的致闪瞬间**。
- 训练页异步读取 `findOpenWorkout`、`workouts`、Cardio、Pelvic 等后再执行 `view.innerHTML`，可能放大交接时的高度与时序差异。

## 4. 已批准行为／不得改变

- 五 Tab 顺序、胶囊形态、20px 图标、可点热区、全量导航状态与相邻页只读预览优先级；非相邻点击亦可前往。
- 顶部标题、历史／日期／子视图状态及实际记录服务；当前页重复点击不触发重播／重建；新的用户点击优先于旧异步响应。
- 边缘返回、纵向滚动、图表水平滚动、Food 日期滑轨、文字选择、文本输入、键盘、Dialog 和 immersive training 优先级不变。
- 饮食、训练和进度不得转为静态模拟数据；实际数据与真实 UI 订阅须保持完整。

## 5. 原型／视觉基准

继续用**已冻结的 v0.4**（`design/reference/2026-10-22-combined-interaction-v0.4/`）；它是视觉与手势行为基准，不提供可直接迁移的生产业务代码。用户最近的两段生产录屏是 BUG 证据；勿将 v0.5–v0.7.1 当作本轮批准设计，也勿更改冻结原型。参考 `docs/COMBINED_INTERACTION_V04.md`。

## 6. 实施范围与技术要求

1. 最优先排查 `src/main.ts` 的 `render()`、`prepareTabPreview()` 及各 tab `render*Page(preview?)`；`src/ui/horizontalNavigation.ts` 的 `prepare/draw/finish/clean/go`、`src/styles/horizontalNavigation.css`。必要时小范围修改 UI renderer 生命周期/样式；防止大重构。
2. **确保一个明确的呈现所有权模型**。推荐：把真正的目标页内容准备为即将显示的可激活视图，令其在动画完成时成为已绑定且有用的实际主页面；或者采用有帧证据证实的无缝合成交接。两种方案都必须完全保留源与目标 DOM 的可见连续性。
3. 如复用预览作为正式页，必须补齐事件绑定、observer/liveQuery、aria 当前状态、唯一 DOM id、当前日期和业务视图装载、stop/dispose，禁止“双份活跃业务订阅”。不可因 preview 跳过绑定而直接删去惯常 render 调用。
4. 正确划分只读预览 vs 正式可交互路由：非当前预览不得触发写操作或后台训练状态；激活只有一次，old view 的清理只在安全交接点运行。
5. 不允许“更改整体渐变淡入”来掩盖刷新、全局 fade overlay、空白中间帧、无界限无限缓存或大范围 React/router 迁移。
6. 保留 `rootRenderVersion`、日期/业务 request token、AbortController、latest-click-wins，处理准备慢、重按、反向拖动、手势取消、resize、pagehide、Dialog 打开、reduced motion 等竞态。
7. 保留每 Tab 与当前子页面必要的 scroll、展开态、过滤态、趋势时间范围、Food 当日选择、训练执行状态。不要对另一 Tab 的异步结果执行 DOM commit 或写库。
8. 仅仅减少 `innerHTML` 数量不算通过：检查训练页来自真实读取的 UI 是否在过渡中完成排版、顶部与内容坐标是否完全稳定；同时检查主导航胶囊和固定 Safe Area。

## 7. 数据安全和历史合同

- `fitlog-lite-db`、Dexie13/IDB130/22 stores、Backup14、Restore1–14、手动加密 GitHub Sync1/envelope1 不变。
- 不改业务持久化、schema、迁移、导入、数据权限、WorkoutAutosave、FoodLog 快照、日期本地历法、训练 Timer/WakeLock/Audio；不读写任何个人健康资料。
- 合成 profile 从升级前到升级后在线重开和离线冷启动，全部22表原始记录与8类配置摘要相同（除测试中明确执行的模拟记录操作）。不能以重置数据库完成测试。
- 既有冻结 fixture 保持字节不变。参阅 `docs/DATA_PRESERVATION.md`。

## 9. 视觉验收

- BEFORE/AFTER 同一模拟档案、同视口、同字体、同主题、同数据；至少 320 / 375 / 390 / 430px、浅深色、100% / 140% / 200%、短屏/横屏和 Reduced Motion。
- 分别录制 `今日→计划→饮食→训练→进度` 与反向，以及快速交替点击 `今日↔训练`、`训练↔饮食`、`进度↔今日`；每次保留过渡前／25%／50%／75%／最后两帧／稳定后的截图和时间线。
- 可见区相邻合成帧不得出现背景白／暖纸闪帧、低高度空块；页面在 commit 后不得二次上/下跳动，典型卡片坐标变化 <= 1 CSS px（真实数据变更除外）。
- 在 before/after 样本结构相同且未发生业务更新时，目标 UI 的节点身份或像素连续性应具可复验的断言；不以“动画时间更短、闪得看不见”替代问题消除。
- 训练页需含三训练入口实际按钮、历史记录状态，点击可打开现有三种 Large Sheet，退出及开始执行无回归。
