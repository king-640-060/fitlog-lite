## 2. 总目标：五个问题一个交付包，但阶段独立验收

A. 清理全 App 冗余解释性小字、重复状态、常驻手势教学，并处理文案断行与缩进。

B. 完成力量训练**单次记录的独立、可选名称**；保存为模板后可选择给当前未命名训练同步命名，模板后续改名不追溯历史。

C. 将现有**空白训练**能力以易懂的**自由训练**入口提供：只练一个动作也正常完成并显示紧凑历史，不强制保存模板，允许主动建立单动作模板。

D. 新增**Classic + Light Native 两套视觉主题**可切换；仅两套，保留经典主题的旧明暗模式（跟随系统/浅/深）及现有用户设置；Light Native 为固定浅色视觉。

E. iPhone **睡眠原生上下时间滚轮**适配 App：保持 `input type="time"` 系统 picker 能力，整合输入框/Sheet/键盘/焦点/颜色与 Safe Area；绝不把不可靠的网页仿制滚轮替换到真实输入流程。

### 明确排除

- `src/db/types.ts` 的 `Workout` 当前没有 `name`；`WorkoutTemplate` 有 `name`。`src/services/templateService.ts` 的 `workoutTemplateFromWorkout(workout,name)` 生成新模板，`startWorkoutFromTemplate` 拷贝动作/组但不存模板名到本次 Workout。这是用户出现“模板后来命名不影响历史训练名称”的实际原因。
- `src/services/workoutService.ts` 已有 `createWorkout`、`normalizeWorkoutForSave`、`saveWorkout`、`finishWorkout`、`WorkoutAutosaveController`；`src/main.ts` 已有保存训练为模板流程和训练完成页。应**在现有机制扩展**，不可另起未经保护的训练编辑器。
- `src/ui/recovery.ts` 的 `showSleepBackfill`、`showSleepEditor` 已用原生 `input type="time"`，通过 `recoveryDatePicker` 选择日期、`sleepNightLabel` 归属夜晚；`src/utils/sleepBusinessDate.ts` 及 `recoveryService` 拥有历史/跨午夜规则，不能用前端计算重写。
- `src/ui/weightChart.ts` 与 `src/ui/recoveryLineChart.ts` 的图表存在冗余图注；`src/ui/trendModule.ts` 用 `trendSelectionHtml` 显示选中数据/无数据状态。原有缺测不补零语义必须保留，**可以删除解释文字但不可删缺测行为或有意义的状态**。

**直接删/合并的优先清单（需核实现在的实际渲染路径与现有重复内容）**：

1. 体重图常驻技术图注“线段仅连接测量点，缺测不补零”。保留图表真实缺测逻辑、选中值与日期。
2. 睡眠/饮水图的“每天保留日期，未记录留空”。保留日期轴和空值本身。
3. 进度已有“未记录”又显示“此范围暂无记录”“0 天有记录”的重复表达：只保留语义完整的一组，不得清除时间范围/单位。`0 天有记录` 的状态不能被错误替换成数值 `0 kg`。
4. 有氧卡片常驻设备例举“楼梯机 · 跑步机”及与“当日记录 0 次”重复的“今天还没有有氧训练”；按**实际当前状态**条件化。
5. 力量卡片“记录动作与组数”等功能教学。已显示动作数量、组数与记录列表时删重复说明，必要时空态只留短引导。
6. 凯格尔卡首页的重复宣传式简介；呼吸、不适停止、禁忌等训练安全说明留在执行/帮助流程。
7. 今日、计划、饮食已有数据后仍然持续出现的“你可以在这里记录/按餐次更清楚/有需要时随手记”等句子；任务/餐次为空时不要同时重复 0 项和“尚未记录”两三次。
8. 管理中心分类已经有标题和入口的情况下，多余“按用途查找”或同义说明，重复广告式引导；保留真实安全说明和 13 项。
9. 弹层里的重复操作教学、无关广告语；对有真实意义的输入提示、异常校验、风险解释只能压缩/重定位，不得丢。

交付**文案清单**：`源文件:行号 / 页面与状态 / 旧文案 / 处理（删、合并、条件显示、保留）/ 理由 / 相关风险 / 截图对照`。不允许只声明“扫描过”。

## 5. B + C：自由训练及本次独立命名

1. 入口沿用已有空白训练，改为“自由训练”；仅一个真实动作和有效组数即可完成且可以在历史/日历/报告中正确显示。训练动作可多可少，**绝不强制保存模板**。
2. 本次记录新增**可选** `Workout.name?: string`（字段名仅作建议，以真实模式与校验命名一致为准）；输入空白或旧历史缺字段时，显示稳定中性的标题或单动作实际名称。显示标题不能被持久化为虚假的已填写名称。
3. 已有记录允许修改/清空本次名称；保存后在首页、训练历史、日期详情、完成页、恢复/重开后显示一致。只改名称不能触发动作/组数重算。
4. 保存为训练模板默认复制动作/组事实创建新模板。加入**“同时命名本次未命名训练”**的明确勾选项：仅在本次记录尚无用户自定义名称时可以修改这条记录；已有自定义名称时必须保留原名，无须“同步”覆盖。模板以后改名/删除，历史名称和真实动作快照都不随之改变。
5. 从模板开始训练，创建当次 Workout 后可以**快照**模板当时名称（或者用户显式确认新名称），不可依赖 template ID 动态显示“当前模板名称”，以免后改模板追溯修改历史。
6. 单动作历史条目可使用紧凑卡片，完整动作、组数、时间、备注仍可点开查看；多动作沿用现有强度结构。不得为美观藏实际记录。
7. 原有效组数/重量/RPE/备注、未完成训练接续、Autosave、确认完成、训练状态机、删除保护、训练中的草稿必须保留；多次快速触发完成/另存模板不能双写/覆盖。
8. 训练完成后模板另存失败，原本训练不被删除或中止；若“同步命名”与保存模板属于一次不可分割用户确认，生产实现应在受控 DB 事务完成两项写入，避免仅部分成功；业务允许拆分时应明确反馈失败和部分成功，不能谎称整体完成。
9. **数据兼容风险是硬门槛**：`Workout` 新增持久字段对 Dexie store index 本身可能无需变更 `db.version(13)`，但必须实际核实 Backup V14 JSON validator/exporter/Restore V1–14 与 Sync V1 是否会拒绝或丢失字段。不能将字段只存 `localStorage` 或塞进 `note`。如需新增 Backup V15/新 Restore validator 或 Dexie 迁移才可无损持久化，应依据项目数据合同以兼容增量方式实施和加冻结测试；**不得在未审查的情况下声称合同未变**。若必须改变已批准的外部合同语义，先提交兼容设计核查。旧备份仍可恢复，旧记录仍无损。

## 6. D：两轴主题系统

- 视觉主题 `classic`、`light-native` **恰好两项**。新增独立偏好键（建议 `fitlog-visual-theme-v1`），不覆盖既有 `fitlog-appearance-v1`。均仅设备本地存储，不进入业务 DB/Backup/Sync，不清除或重置旧偏好。
- Classic 恢复 v0.6.1 已存在的经典浅色视觉、旧明暗设置（三态 `system/light/dark`）和原 dark 的已有行为；**不要从 Light Native 反推 Classic，须从冻结 commit diff 恢复有证据的 token 与组件覆盖**。
- Light Native 固定使用现有批准的浅色 v0.5.1 系统，且不改写原用户旧明暗偏好。返回 Classic 时恢复旧选择（包括跟随系统），切换不刷新整页、不清空 Sheet、编辑草稿、焦点与滚动，不闪屏/混色。
- **升级首次启动保持旧用户当前可见效果**：旧偏好为 dark、或 system 当前为暗 => 仍显示旧深色；旧偏好亮、或 system 当前亮 => 仍显示当前 Light Native 浅色。首次未选新视觉偏好时要保证系统明暗后续响应符合旧行为；用户明确选择主题后按选择锁定相应视觉策略。建议设计区分 “未显式选主题”的兼容自动态与用户主动选择，但 UI 仍只显示两套视觉主题选项，不新增第三种主题。
- 管理中心 → 外观设置：视觉主题单独单选；Classic 明暗设置条件呈现/可保存；Light Native 说明固定浅色。语义访问：radio checked、label、键盘和 VoiceOver 正确。
- 全面覆盖 5 Tab、管理中心四分区 13 入口、Sheet/editor/confirm/toast、Food 日期轨、趋势图/日历、训练执行页与离线 PWA；不能只有首页更新。
- 需要连带更新 `theme-color`、PWA 状态栏方案与 CSS `color-scheme`，不能出现系统控件黑色、页面白色互相冲突；保持已有暗色模式能正常输入。
- 优先 CSS tokens/主题根类，不重复业务渲染器，不复制旧全部 DOM 或两个应用实例。主题切换只改变视觉，不得触发持久化业务写入。

## 7. E：睡眠时间滚轮
