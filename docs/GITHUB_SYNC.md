# Encrypted GitHub Manual Sync V1

IndexedDB is the working database; GitHub is a user-controlled encrypted recovery copy. All network activity is initiated by a user under Management → Data & Backup → GitHub Sync. Manual JSON Backup remains independent.

Create a separate **Private** repository (for example `fitlog-lite-data`) and initialize a README. Create a fine-grained Personal Access Token with **Only selected repositories**, select only that data repo, and grant **Contents: Read and write**. No Actions, Administration, Issues, Pull Requests, Workflows or organization permission is required. Enter owner/repo/token in the app. Public, archived and uninitialized repositories are blocked. Branch comes from repository metadata; remote path is fixed to `fitlog/latest.enc.json`.

The token is stored only on this device in `fitlog-github-sync-token-v1` localStorage. Config and baseline have separate versioned keys; none enter business Backup. This is a convenience tradeoff: same-origin JavaScript/browser access can read localStorage credentials. Use the minimal scoped token and revoke it in GitHub if necessary. Disconnect removes the three sync keys and memory password, not local records or remote files.

A distinct data password is needed to decrypt backups. On first upload choose and confirm at least 12 characters. The app never persists the password or AES key; after successful validation/upload it may retain the password only during the current JavaScript session. Every existing remote must successfully decrypt and validate before replacement. Forgotten passwords cannot be recovered by FitLog.

Envelope V1 contains only protocol metadata and encrypted ciphertext: PBKDF2 HMAC-SHA-256, 310000 iterations, fresh random 16-byte salt, AES-GCM 256-bit key, fresh random 12-byte IV, 128-bit authentication tag. Native Web Crypto only; no encryption dependency. Full UTF-8 Backup is inside ciphertext. The V1 plaintext payload limit is 20 MiB; larger backups use manual export. Unsupported or malformed envelope parameters fail before expensive key derivation. Encryption is authenticated; never claim absolute security.

Canonical SHA-256 fingerprints exclude exportedAt, sort object keys and top-level entities by id, and preserve nested semantic array order. A read transaction captures a consistent complete Backup. Local-only changes may upload; remote-only changes require confirmed Restore; both changed and different content require explicit conflict resolution. Same actual data with a different envelope SHA updates baseline. Fresh starter-only devices prefer remote recovery, never an automatic empty upload. Missing files after pairing require explicit recreation. PUT includes current remote blob SHA, and a race refetches then stops without retry. Failed or ambiguous uploads do not advance the baseline; inspect again before resolving.

Restore decrypts, parses, validates, previews timestamp/counts, offers local export when real local data exists, then calls existing transactional restoreBackup after explicit confirmation. Local and remote changes since preview abort the replacement. Upload never modifies business stores. No background sync, merge engine, multi-user service or automatic remote deletion is provided. Other devices must reconnect and supply the data password.

Normal upgrades preserve local data under DATA_PRESERVATION.md. Clearing site data, removing a profile, storage eviction, uninstall behavior, changing origins/devices can still remove local copies. Recovery requires an existing remote encrypted backup, repo access and the data password. Git history can retain encrypted previous versions; V1 has no history browser.

Implementation references: [GitHub Contents API](https://docs.github.com/en/rest/repos/contents), [GitHub Git Blobs API](https://docs.github.com/en/rest/git/blobs), [Web Crypto PBKDF2/AES-GCM](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey). GET handles larger Contents files via their immutable Git blob SHA; never uses a user/server-provided download URL for credentials. API errors are categorized without exposing server response bodies, tokens, passwords or decrypted business data.
