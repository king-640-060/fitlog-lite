## 饮水和图表

Today 左侧累计、右侧统一 SVG disclosure；默认收起，展开/成功写入后只在必要时定位操作区。`revealOwnedContent` 寻找真实纵向滚动 owner，结合 VisualViewport 和实际底栏边界，尊重 reduced-motion。普通 liveQuery、设备参考值更新不触发定位。保留成功后才更新、双击忙碌保护、独立 WaterLog、精确 Undo、历史、参考值和紧凑 Progress Sheet。数字使用不可见且 aria-hidden 的布局参照，避免 0→500/Undo 在窄屏改变卡片高度；不写业务数据或配置。

体重、睡眠、饮水仍是三个独立模块，既有初始30天保持，每张独立切换7/30/90、选择及横向滚动。七天展示七个自然日位置；30/90保留每天并内部滚动。七天用简短日号，完整业务日期可从选中读数/日期 title 获取，月份跨度在覆盖行明示；长区间另在月初显示月份。没有事实的日期不生成零值/可选事实点。体重连线明确只是连接测量点；睡眠缺失分段，active 不计完成时长。

最近90天真实数据提供同一 Y 参考域，只裁切横向范围。Weight 保持 Chart.js、视口大小 Canvas 和多年历史；Sleep/Water 保持共享 SVG、ScreenCTM 命中和独立读数。批准 v0.3 的全宽绘图取代旧侧边 Y 标签占宽，完整事实值仍显示于 HTML 读数；三个网格线与参考域保留。七天 SVG marker 按实际坐标变换保持圆形，所有 observer/listener 属于 mount 生命周期。已有附近历史、当天记录、睡眠补录动作保留，不复制原型演示导航或数据。

同一视口/字体/主题/数据集切7→30→90→7时，卡片、标题、读数、scroll、Canvas/SVG、日期轴、range、覆盖行和帮助行均须高差≤0.5px。使用实际内部布局而非仅固定外卡：绘图 `10.125rem`（标准162px），日期轴 `2.75rem`（44px），纵向 scroll 为二者之和；7天只横向适配。读数的真实90天文本参照预留本模块最大自然换行高度。不同字号可增长，范围切换不可改变高度。所有七日标签必须可见且文字不相互覆盖；实际量测见本轮 QA。

## 两种只读报告

顶层仅「日常综合报告」「营养周期报告」。周/月/自定义及周期报告的营养、训练、恢复和适用习惯章节使用默认收起的原生 disclosure，保留全部原专业事实；同窗口动作/指标/实时刷新保留用户展开状态。章节采用原生block布局，消除既有grid对闭合内容的额外间距；标准字号闭合卡58px、summary点击区44px，放大时自然增长，正文与事实保持完整。日报的十类事实仍使用既有逐项详情。日常保留日/周/月及完整每日十类事实；自定义以两个现有业务日期选择器选择最多366个自然日，错误范围不提交。模板筛选支持真实 cycle 或真实 phase，phase 显示「模板使用阶段 · 非正式排程周期」，不伪造 cycle/day 排程。无对应周期/阶段时筛选仍可使用。默认优先当前真实周期、当前阶段，再历史范围；显式未来范围保持尚未开始。

关键事实显示热量快照完整日、真实完成训练、体重记录日与完成睡眠覆盖，不把热量完整冒充全部宏量完整。最多三条建议及可展开的事实/判断边界位于专业章节之前，遵循科学报告合同顶部观察规则；保留原型的简洁章节与逐级展开，不复制参考图中旧版演示文案。

两类窗口使用同一个 `loadCoachReport` / `ReportSource`、动作匹配与合格完成规则、完整宏量/同日正目标配对、恢复聚合及确定性最多三条「事实 / 局限 / 下一步」观察。Task/subtask 只保留在原每日事实详情，不参与运动科学分析。完成力量的已记录组不冒充有效工作组，外部负重×次数不代表能耗或增肌。保留所有动作历史、可比条件、首次/模糊身份/混合变化、完整保存快照。

体重以同日最后有效记录作为每日代表值；7日平滑均值只在该窗口至少3个记录日时展示，缺测不补值，门槛明确是产品展示规则。g/kg 的统计详情说明同日体重值和日期，不推断个人需要量。睡眠按完成业务夜晚求和；起止时刻均值和平均偏差使用每晚最长片段与循环时钟，至少3晚才展示偏差，不能当健康评分。饮水提供有记录日均值/覆盖，不以设备参考值诊断脱水。未来日期不进入实际分母。无 TDEE、确定能量赤字、身体成分、REDs、过度训练或脱水诊断，无新增 AI 评语请求。

参考边界沿用批准包的[依据](../design/reference/2026-10-17-joint-v0.3/07_EVIDENCE_BASIS.md)。已核实论文条目及可取得的摘要内容：[IOC REDs 2023](https://pubmed.ncbi.nlm.nih.gov/37752011/)、[运动员睡眠共识](https://pubmed.ncbi.nlm.nih.gov/33144349/)、[ACSM 饮水立场](https://pubmed.ncbi.nlm.nih.gov/17277604/)。BMJ 原链接读取遭403；IOC摘要另从NCBI BioC取得，饮水摘要从PubMed取得，睡眠条目正文/摘要另遇限流，未声称已阅读全文或完成独立文献评审。实现边界以批准合同为准，没有从摘要导出个体医学阈值。

## 新的危险删除边界

新增 `nutritionRangeCascadeService`，管理危险入口使用它；`nutritionStrategyCascadeService` 仍只删除旧六类，`deleteUnusedNutritionStrategy` 仍检查无引用，`clearDayRecords` 和普通逐日删除没有扩大。

来源是该模板所有 phase 和 cycle（包括归档/未来）的闭区间并集；open phase 截到预览/确认一致的本地今天。合并重叠与相邻段，保留不连续间隔。无来源则不推测日期。预览列出每个来源、状态、并集、日数、已到/未来日期及每类数量。

精确删除六类归属对象，加日期并集中的九表：foodLogs、weights（同日所有ID）、waterLogs、sleepSessions（`resolveSleepBusinessDate` 整段ID）、workouts、cardioSessions、pelvicFloorSessions、dietEvents、habitCheckIns。nutritionTargets = 六类关联目标 ∪ 并集内全部来源目标，分别列「来源关联」和「额外区间」数量。明确告知这些事实可能不是模板产生、手动/饮食模板目标也会损失，未来范围仅影响已有对象。

始终保护 tasks（含 subtasks/日期/完成）、taskTags、foods、exercises、workoutTemplates、dietTemplates、habits 定义、其他模板及区间外事实。只按精确ID bulkDelete；绝不 clear、调用清日或垃圾回收。

预览为22表一致 readonly 快照，按表/ID/对象键规范化指纹，包含本地今天和所有潜在对象。勾选后仍需第二危险确认；取消/关闭/导航不写。确认后一个覆盖22表的 rw 事务重读全部、重算范围/候选/冲突并复核指纹；十五表只写批准 ID，另外七表仅锁定读取校验。后置验证所有22表完整内容恰为前快照减批准ID，重新检查营养归属、目标引用和周期不变量，任何异常整体回滚。事务中没有UI、网络或 timeout。原生关闭、取消或预览被替换会取消排队操作；事务中收到取消则 abort 并回滚全部表。监听器/observer 属于该预览生命周期，结束后释放。

其他模板任何阶段/周期（包括归档）与有效日期交叠、混合/交叉来源、缺失 phase/cycle/日方案、非法排程、无法确定业务日期均整次拒绝。合法已移除日方案快照继续可读/恢复；但本轮扩大删除遇到这种缺失来源时明确拒绝并要求核对，不自动补建历史定义。旧六类 API 的历史快照语义不改变。

范围内 active Sleep 或未完成 Workout 拒绝，提示先结束/取消后重新预览。内存凯格尔运行态使用 runtime-only Web Locks 日期 lease；危险操作先独占 gate，查询其他窗口正在运行的相关日期，再进入 IDB 事务；新训练启动同 gate 协调。范围内运行或保存/完成未返回的凯格尔会阻止整次删除，需在原窗口完成/手动结束并返回。无 Web Locks 的浏览器拒绝这一危险路径，不降级成不安全删除。未给旧版未知窗口作虚假跨版本运行态保证；原安装设备升级、真实生命周期仍需用户验收。

已完成力量训练的迟到自动保存/完成使用原子“必须仍存在”检查，保留内存草稿并拒绝复活已删除ID；有氧编辑读取与写入在同表事务内，避免跨窗口删除后旧编辑重建ID。

成功由现有 liveQuery/重新读取刷新 Today、三趋势、Calendar、两类报告和管理器；不存在的 cycle/phase 不再可选，不从缓存重建目标。删除只作用当前设备 IDB；旧备份/远端副本不自动销毁，用户显式 Restore 仍可恢复原数据。无自动 Sync/上传/远端清理。
